# LLM 스타일 파라미터 생성 (중간보고서 5.1절)

명령 하나를 Qwen3-4B가 스타일 파라미터(s, n, m, δ, c) JSON으로 바꾸고, Python은 형식과 검증 범위만 검사한 뒤 `run_style_walk.py`가 읽는 `variants.json`으로 옮긴다. 참조 모션과 보상 함수의 형태는 그대로이다.

`test_commands.json`(1세트)은 프롬프트와 퓨샷 예시를 쓰기 전에 작성하여 커밋하였다. 첫 실행(프롬프트 v1, 20261026_152019) 결과를 본 뒤에는 개발용으로만 쓰고, 프롬프트 v2의 평가에는 v2를 고치기 전에 작성한 `test_commands_2.json`(2세트)을 쓴다. 2세트의 3단계 결과를 본 뒤에는 2세트도 개발용으로 돌리고, 프롬프트 v3의 평가에는 v3를 고치기 전에 작성한 `test_commands_3.json`(3세트)을 쓴다. 각 세트는 첫 실행 뒤에 고치지 않는다. 4세트는 프롬프트 v4(동작 선택)를 쓰기 전에 작성하였다. 프롬프트 v5(2026-11-03에 고정한 수식에 맞춘 사전)의 평가에는 v5를 고치기 전에 작성한 `test_commands_5.json`(5세트)을 쓰고, 같은 명령에서 비교하기 위해 v4도 5세트로 실행한다. 4세트는 v5의 개발용이다. 5세트의 수락 명령에는 명령의 핵심 특징에 필요한 값 기준(`check`, 기본값을 채운 파라미터에 대한 Python 식)을 결과를 보기 전에 적었다.

## 판정 기준 (결과를 보기 전에 정함)

1단계, 자동 검사 (`style_parser.py --test`)
- A, B 묶음: 유효한 파라미터를 내면 통과, 거절하면 실패.
- C 묶음: 거절하면 통과, 파라미터를 내면 실패.
- 유효한 파라미터: JSON 객체 하나, 정해진 키만 사용, 모든 값이 검증 범위 안, 어깨 굴곡과 외전은 둘 중 하나만 사용.
- 형식 오류는 한 번만 다시 생성하고, 그래도 오류면 실패로 센다.

2단계, 사람 평가 (파라미터가 명령의 의미에 맞는가)
- 2점: 명령의 핵심 특징이 모두 파라미터에 반영되고 과한 값이 없음.
- 1점: 방향은 맞지만 핵심 특징 일부가 빠지거나 값이 지나치게 크거나 작음.
- 0점: 의미와 반대이거나 핵심 특징이 반영되지 않음.
- A 묶음은 `ref` 스타일과 값의 변화 방향이 같은지도 함께 본다. 수치가 주어진 명령(각 세트의 B10)은 항목의 `check` 조건을 만족해야 2점.

3단계, 영상 평가 (학습한 동작이 명령과 맞는가, 각 2,000회 반복)
- 2점: 명령의 특징이 영상에서 분명히 드러남.
- 1점: 일부만 드러나거나 약함.
- 0점: 기본 보행과 구분되지 않거나, 다른 동작이거나, 넘어짐.
