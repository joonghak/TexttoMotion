# 공개 T2M 모델과의 비교 (2026-11-12 시작)

교수님 의견(2026-11-12): 평가는 우리 방법이 잘하는 축에서, 공개된 text-to-motion(T2M) 모델과 비교하여 "다른 모델은 못 하고 우리는 한다"를 보인다. 100STYLE 유사도는 한 배우의 해석에 맞추는 지표여서 우리에게 불리하므로 개발용으로만 쓰고, 최종 비교는 아래 측정과 사람 평가로 한다.

## 비교 모델 (공개 코드와 사전학습 가중치)

- MoMask (Guo et al., CVPR 2024), T2M-GPT (Zhang et al., CVPR 2023), MDM (Tevet et al., ICLR 2023). 모두 HumanML3D로 학습하였고 영어 문장을 받아 SMPL 관절 22개의 위치(20 fps)를 낸다. 코드는 저장소 밖 `/home/jong/baselines/`에 두고, 이 GPU(sm_120)를 위해 torch 2.7.0+cu128 가상환경(`/home/jong/baselines/venv`)을 따로 만들었다. 우리 명령은 영어로 옮겨 준다(`test_commands_8.json`의 en, 6·7세트는 `commands_en.json`).

## 비교 축

1. 수치를 따르는 정도: 8세트(`experiments/style_llm/test_commands_8.json`)의 명령은 각도, 박자, 속도, 보폭을 숫자로 말한다. 생성된 걸음에서 그 값을 재어 말한 값과의 차이를 비교한다(`measure.py`). 각도는 같은 방법의 기본 걷기("A person walks forward.")와의 차이로, 박자와 속도는 절대값으로 잰다.
2. 물리적 타당성: 땅 뚫기(penetration_cm), 떠 있음(floating_cm), 디딘 발의 미끄러짐(slide_cm, skate). 정의는 `measure.py` 머리말에 있다. 우리 정책은 물리 시뮬레이션에서 나오므로 이 값이 거의 0이다(기본 걷기: 0.03 cm, 0, 0.06 cm, 0%).
3. 스타일과 동물 흉내: 6세트와 7세트 명령의 영상을 같은 캐릭터로 렌더링하여 사람이 고르게 한다(사람 평가, 설계는 사용자와 정한다).

## 결과 (2026-11-12, 비교 모델 쪽)

세 모델 모두 명령마다 세 번(시드 셋) 6초씩 생성하였다. MoMask는 가장 긴 길이(196프레임, 9.8초)를 강제하면 걷기 명령에서 거의 제자리에 서 있는 동작을 내므로, 학습 데이터 길이 안쪽인 6초(120프레임)로 생성하였다. T2M-GPT는 길이를 스스로 정한다(끝 토큰까지).

수치를 따르는 정도(8세트, `out/<모델>_report.md`). 세 모델 모두 숫자를 따르지 못하였다. 상체 20°와 40°에 MoMask −3~−7°, T2M-GPT 2~15°, MDM −3~9°였고, 분당 90걸음에 세 모델 모두 92~133걸음, 초속 0.6 m에 0.9~1.3 m/s, 보폭 1.5배에 0.84~1.14배였다. 팔을 옆으로 45°는 MoMask와 T2M-GPT가 89~149°로 머리 위까지 들었고, 팔을 앞으로 90°는 2~9° 또는 잴 수 있는 걷기가 나오지 않았다. 다리 10°(T2M-GPT 10, 10, 20°)와 무릎 30°(T2M-GPT 20~23°)만 비슷한 경우가 있었다.

물리 지표. 떠 있음(가장 낮은 발 관절이 1 cm 넘게 뜬 높이의 평균)은 MoMask 4.4~9.5 cm, T2M-GPT 1.3~2.9 cm, MDM 3.2~4.1 cm였고, 디딘 발의 미끄러짐(중앙값)은 1.4~2.6 cm였다. 우리 정책 38개는 떠 있음 0 cm, 미끄러짐 0.04 cm, 땅 뚫기 0.025 cm였다(물리 시뮬레이션의 접촉 허용 오차 수준). MoMask의 기본 걷기에서는 두 발이 모두 10~20 cm 떠 있는 구간이 길었다.

100STYLE 유사도(6세트와 7세트, 우리 LLM 답과 같은 지표, 각 모델의 기본 걷기 기준). 곧게 2초 이상 걷는 구간이 없는 출력은 우리 LLM의 거절과 같게 0점으로 셌다(세 모델 출력의 23~43%).

## 진행

- 2026-11-12: 저장소 세 개와 가상환경 준비, 세 모델의 출력 생성과 측정. 외부 코드 실행은 사용자가 허용하였다. 우리 쪽 8세트는 gpt-5.6-luna(v10)의 답을 학습하는 중이다(Q9 무릎 30°에 c 30을 골라 무릎이 60° 굽는 답이 나왔다. 프롬프트의 c 설명이 "knee bend"로 시작하여 헷갈리게 쓰였으며, 다음 프롬프트에서 고친다).

## 결과 (2026-11-12 밤, 8세트의 우리 쪽)

gpt-5.6-luna(프롬프트 v10)가 정한 값으로 학습한 정책 13개를 캐릭터 4개로 30초씩 기록하여, 비교 모델과 같은 방식으로 측정하였다(`out/ours_set8_20261112_154003_luna_v10_set8_trained_report.md`, 표는 `out/set8_compare_20261112_154003_luna_v10_set8_trained.md`, `compare_set8.py`). 13개 명령 가운데 12개에서 우리의 오차가 가장 작았고, 말한 값에 대한 상대 오차의 중앙값은 우리 5%, MoMask 95%, T2M-GPT 78%, MDM 80%였다. 속도(초속 0.6 m와 1.8 m)는 0.60과 1.80 m/s로 맞았고, 박자 140걸음/분은 138, 팔 옆으로 45°는 44.9°, 다리 벌림 10°는 10.1°, 고개 30°는 31.5°였다. 넘어진 기록은 없었고, 땅 뚫기 0.02 cm, 떠 있음 0 cm, 디딘 발 미끄러짐 중앙값 0.10 cm였다.

상체 기울기는 두 가지로 측정하였다. 골반에서 목까지의 선으로 재면 20°와 40°의 명령에 9.5°와 18.8°로 절반이 나온다. 이 캐릭터는 골반과 목 사이의 가운데에 있는 관절 하나에서 상체를 굽히므로, 골반 부분은 서 있고 그 위의 상체만 기울기 때문이다. 허리(우리 몸통 관절, HumanML3D에서 같은 높이에 있는 spine2)에서 목까지의 선으로 재면 19.3°와 38.8°였고, 영상에서 보이는 상체의 기울기도 이쪽과 맞았다. 비교 모델은 어느 쪽으로 재도 거의 기울지 않았다(−6~9°).

유일하게 진 명령은 Q9(무릎 30° 더 굽히기)이다. luna가 c 30을 골라 무릎이 57° 굽었다. 프롬프트 v11부터 c 설명을 "무릎을 2c만큼 굽힌다, K도는 c = K/2"로 고쳤고, 같은 명령에 v12의 luna는 c 15(목표 동작에서 무릎 +30.0°)를 골랐다.
